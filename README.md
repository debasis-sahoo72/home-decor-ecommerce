The project includes architecture, setup, authentication, catalog and product pages, persistent carts and wishlists, addresses, standard-delivery checks, checkout, customer order tracking and an initial admin dashboard. See [order management and administration](docs/order-management.md), [delivery and checkout](docs/delivery-and-checkout.md), [catalog and storefront](docs/catalog-and-storefront.md) and [product detail](docs/product-detail.md). Razorpay finalization and public deployment remain later phases; pending orders can be saved without enabling payments.

Local project folder: `C:\Users\sonal\Projects\home-decor-ecommerce` (outside OneDrive).

After completing the first-time setup, start or verify all local services from the
project root with `powershell -File .\scripts\start-local.ps1`. It starts the bundled
PostgreSQL service when present, applies migrations, starts missing app servers and
checks database readiness. Keep all three services running while viewing the site.
Background server logs are in `.tools`. An empty catalog is different from an outage:
real products must be entered through the admin API before product cards appear.

For an optional local preview, run `python -m app.seed_demo` with the backend
virtualenv from `backend`. This idempotently adds six `[DEMO]` products, three of
them featured. Prices and stock are examples; each product has four AI-created demo photos. No reviews, orders or delivery rules are invented. The command refuses
production environments and nonlocal database hosts. Remove or deactivate these
demo products before migrating a development database into production.

## Install

Use Node.js 24 with npm 11, Python 3.11, Git and PostgreSQL 17. Docker Desktop is optional. From the root in PowerShell, copy examples **only if local environment files do not already exist**:

```powershell
Copy-Item .env.example .env
Copy-Item frontend/.env.example frontend/.env.local
Copy-Item backend/.env.example backend/.env
cd frontend
npm ci
cd ../backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps --no-build-isolation -e .
cd ..
```

This machine has Node without npm. In `frontend`, replace `npm` with `node ../.tools/npm/package/bin/npm-cli.js`. The ignored npm copy is unnecessary on a standard Node installation.

## Database

Normal installations can run `docker compose up -d db` from the root, or use native PostgreSQL with a login/database matching `backend/.env`. Example credentials are local-only and use port 5432.

This machine now has isolated PostgreSQL binaries/data under `.tools`, using port **55432**. The local backend environment uses this port. It binds to loopback and is not a Windows service. Start from the root:

```powershell
& .tools/postgres/pgsql/bin/pg_ctl.exe -D .tools/pgdata -l .tools/postgres.log -o '-h 127.0.0.1 -p 55432' start
```

Stop with `& .tools/postgres/pgsql/bin/pg_ctl.exe -D .tools/pgdata stop -m fast`. These binaries/data are ignored by Git. Fresh clones need standard PostgreSQL/Docker setup. For ongoing development, keep the repository and PostgreSQL data outside OneDrive to avoid synchronization/locking issues.

From `backend`, initialize/check the schema and optional reference categories:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic check
.\.venv\Scripts\python.exe -m app.seed
```

The initial migration creates 20 tables and integrity/audit triggers. Seeds create three categories, never passwords, reviews, orders or delivery promises. Review future autogenerated migrations and custom trigger SQL. Never downgrade valuable data merely to edit a migration.

## Run

Backend, terminal 1 from the root:

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Frontend, terminal 2 from the root, using this machine's npm:

```powershell
cd frontend
node ../.tools/npm/package/bin/npm-cli.js run dev
```

On a standard installation use `npm run dev`. Open <http://127.0.0.1:3000> for the storefront preview, and <http://127.0.0.1:8000/docs> for API contracts. Authentication requires the CSRF sequence in its guide. Run backend commands from `backend` so `.env` loads; restart/rebuild Next.js when changing `BACKEND_URL`.

Verify in another terminal:

```powershell
curl.exe --fail-with-body http://127.0.0.1:8000/api/v1/health
curl.exe --fail-with-body http://127.0.0.1:3000/api/v1/health
curl.exe --fail-with-body http://127.0.0.1:8000/api/v1/ready
```

Health returns `{"status":"ok"}`. Readiness returns `{"status":"ready"}` with PostgreSQL, or 503 with a safe error envelope and request ID without it.

## Tests

Create a separate disposable `decor_test` database. The isolated instance already has one. From `backend`:

```powershell
$env:TEST_DATABASE_URL='postgresql+psycopg://decor:local-development-only@127.0.0.1:55432/decor_test'
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pip check
```

Use port 5432 for normal Compose. Fixtures apply migrations and roll back test transactions. They refuse names not ending in `_test`; without the URL, integration tests are explicitly skipped. CI supplies PostgreSQL and the URL, runs the suite, checks drift and verifies migration round trips on a disposable database.

From `frontend` (use the npm fallback if needed):

```powershell
npm run check:contrast
npm run lint
npm run typecheck
npm test
npm run build
```

## Admin and operations

From `backend`, use `.\.venv\Scripts\python.exe -m app.cli create-admin`. It asks for email/name and a hidden passphrase twice. Existing accounts are never silently promoted. Run `python -m app.cli cleanup-auth` with the virtualenv daily when deployed to remove expired sessions/rate buckets.

Admin authorization exists. MFA, email verification, password recovery, security hardening and deployment remain launch requirements. See the authentication guide for the full contract.

The configured GitHub remote is `https://github.com/debasis-sahoo72/home-decor-ecommerce.git`. Review `git status --short` before committing or publishing. Secrets, dependencies and PostgreSQL data are ignored.

Versions are locked in npm/Python lockfiles. Argon2 and email-validator are the only additional runtime packages for authentication. ESLint 9 is retained for compatibility with the current Next.js React lint plugin, despite its deprecation notice. Two upstream test-client warnings remain visible.

See [storefront visual direction](docs/storefront-visual-direction.md) for the reference design, consistent image dimensions, demo asset conventions and guidelines for every later page.
